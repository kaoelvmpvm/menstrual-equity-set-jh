# Google 試算表連線：教師設定指南

新版 SET 已能收集班級、座號、姓名，十題每次作答，以及 A 等進階分析。資料先存於學生裝置，學生按「送出學習紀錄」才傳到教師端。

## 1. 開啟教師專用試算表

使用「經彩同行 SET｜學生學習歷程資料庫（教師專用）」：學習總覽、逐題作答軌跡、進階分析三個分頁。
**不要將整張試算表設為「知道連結的任何人都能檢視」。** 只與依法有權處理成績的人分享。

## 2. 貼上接收程式

在試算表中選擇「擴充功能 → Apps Script」。刪除預設空白程式碼，貼上本專案 google-apps-script/Code.gs 的完整內容，儲存。

## 3. 部署網頁應用程式

在 Apps Script 選擇「部署 → 新增部署作業 → 網頁應用程式」。
- 執行身分：我（教師／表格擁有者）。
- 存取權限：任何人（讓學生免登入 Google 即可送出；如果學校不允許公開端點，應改採受控方式，不部署公開接收端）。
- 由教師本人完成 Google 授權。
複製部署成功的正式 /exec 網址；不要使用 /dev 測試網址。

## 4. 設定 SET 網頁

開啟 GitHub 專案 config.js，將 collectionEndpoint 改為剛才取得的 Apps Script /exec URL，再提交修改。**不要**將帳號密碼、私有金鑰或 OAuth token 放在 GitHub。

## 5. 實際測試

1. 用測試班級／座號／姓名進入網站，完成10題；第一題先答錯再答對。
2. 進階分析勾選偏見與資源障礙，填入原因；按「保存我的分析」。
3. 按「送出學習紀錄」。
4. 在教師表格確認：總覽1列、逐題軌跡11列（10題＋一次重試）、進階分析1列。
5. 用相同學習代碼再次送出，應更新分析而非重複新增作答紀錄。
6. 刪除三張工作表中的測試資料。

## 安全限制與備援

- 任何知道公開 Apps Script endpoint 的人都可能嘗試提交資料；它不是正式的身分驗證系統。伺服器做欄位驗證、長度限制、鎖定及去重，無法完全阻擋惡意送件。
- 學生未經登入，班級座號與姓名無法自動驗真。
- 正式蒐集學生姓名及學習紀錄前，請確認校方個資處理與告知程序；不要公開分享試算表。
- 網站以 iframe 送出並等待 Apps Script 回應；若瀏覽器限制跨網站嵌入，可能無法收到確認。請查看實際試算表，並先下載備份。
- 所有作答軌跡是在學生**主動送出時一次上傳**，不是作答當下即時串流。
